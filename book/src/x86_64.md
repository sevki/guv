# x86_64

## Guest

`cruncher` counts `ecx` down from 10,000,000, doing arithmetic in `rax`, then
clears `eax` and jumps to `resume_main`.

## Task layout

```rust,ignore
#[repr(C)]
pub struct Task {
    regs: [libc::greg_t; 23], // same order as mcontext_t.gregs
    pub finished: bool,
    started: bool,
}
```

Keeping `regs` in `gregs` order lets the signal handler save and restore with
a single slice copy.

## Entering

`enter_guest(main_sp, task)` pushes `rbp`, `rbx` and `r12`–`r15`, stores
`rsp` through `main_sp`, loads `RFLAGS` from the task with `pushq`/`popfq`,
pushes the task's `RIP`, loads the general-purpose registers and `ret`s into
the guest. `resume_main` pops the saved registers and returns.

## Switching

- `save` copies all 23 `gregs` into the task and marks it started.
- `restore` copies the task's `gregs` into the context but keeps the
  context's `RFLAGS`, swapping in only the status flags
  (CF, PF, AF, ZF, SF, OF: mask `0x8d5`).

A task that has never run has only `RIP` set. The first time the handler
switches to it, `restore` copies the interrupted context as a template, keeps
the task's `RIP`, and sets `RSP` to `main_sp` so that the guest's eventual
jump to `resume_main` finds the frame `enter_guest` left on the stack.
